
# CLOE — M0.5: Controlled Data Collection & Experimental Protocol

**Project:** Cognitive Load Occlusion Engine
**Milestone:** M0.5 — Controlled Data Collection
**Date opened:** 2026-11-19
**Status:** IN PROGRESS

## 1. Milestone Objective

Design and pilot a reproducible experimental data collection
procedure for investigating the relationship between preliminary
oculomotor features and task-related cognitive workload.

This milestone does not aim to establish a clinically validated
cognitive-load measurement system.

## 2. Research Question

Do preliminary oculomotor features extracted by CLOE vary
systematically across programming tasks designed to induce
different levels of cognitive demand?

## 3. Working Hypothesis

Higher-demand programming tasks may produce measurable
differences in selected gaze-derived features compared with
lower-demand tasks.

The direction, magnitude, and reliability of these
differences are not assumed in advance.

## 4. Experimental Conditions

| ID | Condition | Description |
|---|---|---|
| A | BASELINE | Low-demand visual reference |
| B | LOWER_DEMAND | Simple code comprehension |
| C | HIGHER_DEMAND | More complex debugging task |

The experimental labels describe intended task demand,
not confirmed participant cognitive-load levels.

## 5. Proposed Measurements

### 5.1 Eye-Tracking Measurements

- Valid gaze availability
- Temporal sampling gaps
- Gaze velocity
- LOW/HIGH/UNKNOWN movement-state proportions
- Segment duration and velocity summaries
- Window-level data-quality status

### 5.2 Independent Measurements

- Task completion time
- Task correctness
- Subjective workload assessment
- Session interruptions and deviations

### 5.3 Important Distinctions

Task difficulty is not identical to cognitive load.

Gaze velocity thresholds are experimental and have not been
validated as physiological fixation/saccade thresholds.

Self-reported workload is not an objective ground-truth
measurement of instantaneous cognitive load.

## 6. Participant and Data Protection

- Obtain informed consent before recording.
- Use pseudonymous participant identifiers.
- Minimize collection of identifying information.
- Store raw recordings locally.
- Define retention and deletion procedures before recruitment.
- Keep participation voluntary, including the right to stop.
- Check institutional ethics requirements before involving
  external participants.

## 7. Session Procedure

1. Explain the study and obtain consent.
2. Check device connection and calibration.
3. Verify recording quality.
4. Record the baseline condition.
5. Record the programming conditions.
6. Collect task outcomes and workload assessments.
7. Verify saved files and session metadata.
8. Document problems or deviations.

## 9. Limitations

- Initial evidence is based on limited recordings.
- Experimental velocity thresholds are illustrative.
- Task demand does not directly establish cognitive load.
- Participant variability requires further evaluation.
- Physiological ground truth is not yet available.
- Adaptive interface effectiveness is outside this milestone.
